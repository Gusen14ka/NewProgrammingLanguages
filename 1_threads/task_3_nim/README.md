# Ограниченный буфер производитель–потребитель для показаний датчиков

**Тема:** Многопоточность — Nim

## Описание задачи

Симуляция системы сбора данных с датчиков на классической схеме
«производитель–потребитель» (producer–consumer). Три потока-производителя изображают
три датчика: каждый генерирует 6 случайных показаний вокруг своего базового значения
(20, 30 и 40 единиц) и кладёт их в общий буфер. Один поток-потребитель забирает
показания из буфера.

Буфер — кольцевой (после последней ячейки запись продолжается с первой) и маленький,
всего на 3 элемента. Производители пишут быстрее, чем потребитель читает, поэтому
буфер регулярно заполняется. В этот момент производитель засыпает и ждёт, пока
потребитель не освободит место; аналогично, если буфер пуст, ждёт потребитель.

Синхронизация сделана на примитивах стандартной библиотеки Nim (`std/locks`):
`Lock` (мьютекс — пускает к буферу только один поток за раз) и две условные
переменные `Cond` — `notFull` и `notEmpty`. Условная переменная позволяет потоку
«заснуть» до сигнала от другого потока, не тратя процессорное время на постоянную
проверку.

Программа печатает каждое событие в момент, когда оно происходит: какой датчик что
положил, кто и почему ждёт, кто проснулся, что забрал потребитель, — и сколько
элементов в буфере после этого. Так прямо в выводе видна работа синхронизации.
В конце — проверка целостности: сколько показаний произведено и получено и совпадают
ли их суммы. Если бы синхронизации не было, данные терялись бы или дублировались, и
проверка бы это поймала.

## Формат входных и выходных данных

Входные данные — константы в начале кода: число датчиков, размер буфера, число
показаний на датчик.
Выходные данные — журнал событий с состоянием буфера, число полученных показаний и
ожиданий по каждому датчику, итоговая проверка целостности.

## Запуск

Нужен компилятор Nim (`sudo apt install nim`).

```bash
nim c --threads:on -d:release sensors.nim
./sensors
```
