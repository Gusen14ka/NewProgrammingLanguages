# Сервер для игры в крестики-нолики между двумя клиентами

**Тема:** Клиент-серверное взаимодействие — Rust

## Описание задачи

TCP-сервер для игры в крестики-нолики 3×3 по сети и консольный клиент к нему. Обе
части находятся в одной программе, режим выбирается аргументом (`server` или
`client`). Используется только стандартная библиотека Rust (`std::net`, `std::thread`,
`std::sync`).

Сервер слушает порт и обрабатывает каждое подключение в отдельном потоке. Первый
подключившийся клиент попадает в «слот ожидания» и получает сообщение, что ждёт
соперника. Когда приходит второй, сервер забирает ожидающего из слота и запускает для
этой пары игровую сессию. Слот общий для всех потоков, поэтому защищён мьютексом
(`Arc<Mutex<Option<TcpStream>>>`): два одновременных подключения не смогут занять его
вместе или потерять друг друга. Несколько игр идут параллельно, каждая в своём потоке.

В сессии сервер назначает игрокам `X` и `O`, рассылает обоим текущее поле, просит
ходящего ввести номер клетки (1–9), проверяет ход (число, клетка в пределах поля и
свободна) и после каждого хода проверяет победу по всем 8 линиям и ничью. Если
игрок отключился, его соперник получает победу. Сервер печатает журнал игр.

Клиент подключается к серверу, в отдельном потоке печатает всё, что приходит от
сервера, а в основном отправляет на сервер строки, введённые с клавиатуры.

## Формат входных и выходных данных

Входные данные — для сервера необязательный порт (по умолчанию 7878), для клиента —
адрес `host:port` (по умолчанию `127.0.0.1:7878`); ходы вводятся номером клетки.
Выходные данные — поле, приглашения к ходу и результат игры у клиентов; журнал
подключений и ходов на сервере.

## Запуск

Нужен Rust (`curl https://sh.rustup.rs -sSf | sh` или `sudo apt install rustc`).

```bash
rustc -O ttt.rs -o ttt
./ttt server              # терминал 1
./ttt client              # терминал 2 — игрок X
./ttt client              # терминал 3 — игрок O
```
