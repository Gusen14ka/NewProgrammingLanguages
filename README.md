# NL_2026

Индивидуальная работа: 20 программ на 20 разных языках программирования.
Пять тем, на каждую тему — по 4 программы. Специализированные библиотеки не используются —
только стандартная библиотека каждого языка (потоки/tasks, сокеты, файловый ввод-вывод).

## Порядок работы

Каждая задача делается в отдельной ветке. Имя ветки: `<номер темы>_task_<номер задачи>_<язык>`,
например `1_task_1_ada`. Исходники лежат в папке своей темы: `<папка темы>/task_<номер>_<язык>/`.

## Языки (20 из 26 предложенных)

Ada, Clojure, D, Elixir, Erlang, F#, Groovy, Haskell, Julia, Kotlin, Nim,
Objective-C, OCaml, Perl, Prolog, Rust, Scala, Scheme, Swift, Zig.

Не используются: Lisp, Lua, ML, Mojo, ODIN, Ruby.

## Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Параллельная сортировка слиянием на задачах | Ada | `1_task_1_ada` |
| 2 | Оценка числа π методом Монте-Карло в потоках | D | `1_task_2_d` |
| 3 | Ограниченный буфер производитель–потребитель для показаний датчиков | Nim | `1_task_3_nim` |
| 4 | Параллельное умножение матриц через fork и каналы | Perl | `1_task_4_perl` |

1.1 **Ada.** Массив рекурсивно делится пополам, каждая половина сортируется в отдельной Ada-задаче (task) через рандеву, слияние выполняется в главной задаче; сравнивается время работы последовательной и параллельной версий.

1.2 **D.** Пул потоков (`core.thread`) генерирует случайные точки в квадрате и считает попадания в круг, локальные счётчики складываются в общий под мьютексом; итоговая оценка π выводится вместе с числом использованных потоков.

1.3 **Nim.** Несколько потоков-производителей кладут показания «датчиков» в кольцевой буфер фиксированного размера, поток-потребитель извлекает и усредняет их; синхронизация — через `Lock`/`Cond`, при переполнении буфера производители ждут.

1.4 **Perl.** Строки результирующей матрицы распределяются между дочерними процессами через `fork`, каждый процесс считает свою часть произведения и передаёт результат родителю через pipe; время сравнивается с последовательным вычислением.

## Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | N ферзей: перебор с возвратом (рекурсия) | Prolog | `2_task_1_prolog` |
| 2 | Построение кода Хаффмана (рекурсия) | F# | `2_task_2_fsharp` |
| 3 | Поиск подстроки алгоритмом Кнута–Морриса–Пратта | Kotlin | `2_task_3_kotlin` |
| 4 | Компоненты связности графа через рекурсивный DFS (рекурсия) | Julia | `2_task_4_julia` |

2.1 **Prolog.** Рекурсивный предикат расставляет ферзей по столбцам одного за другим, проверяя конфликты по строкам и диагоналям, и откатывается при тупике; выводятся все найденные расстановки для заданного N и их количество.

2.2 **F#.** По частотам символов текста рекурсивно строится бинарное дерево Хаффмана (объединением двух наименее частых узлов), затем рекурсивным обходом дерева генерируются коды переменной длины и считается коэффициент сжатия относительно ASCII.

2.3 **Kotlin.** Вручную строится префикс-функция образца, затем итеративный проход по тексту находит все вхождения образца; число сравнений сопоставляется с наивным поиском подстроки.

2.4 **Julia.** Граф читается из списка рёбер; рекурсивная функция обхода в глубину помечает все вершины одной компоненты связности, начиная с непосещённой вершины; печатается список компонент и их размеры.

## Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Консольный органайзер заметок с хранением в файле | Groovy | `3_task_1_groovy` |
| 2 | Посимвольная и пословная статистика текстового файла | Objective-C | `3_task_2_objc` |
| 3 | Калькулятор расходов с историей в CSV-файле | Scala | `3_task_3_scala` |
| 4 | Построчное сравнение двух файлов (упрощённый diff) | Haskell | `3_task_4_haskell` |

3.1 **Groovy.** В цикле читаются команды `add/list/search/remove/exit`; заметки с тегами хранятся в собственном простом текстовом формате в файле, который перечитывается при старте и перезаписывается после каждого изменения.

3.2 **Objective-C.** Программа читает текстовый файл и считает число строк, слов, самое длинное слово и частоту каждой буквы алфавита; сводка выводится в консоль и дописывается новой записью в файл-журнал статистики.

3.3 **Scala.** Пользователь с консоли вводит операции дохода/расхода с категорией; каждая операция дописывается строкой в CSV-файл, при запуске программа читает всю историю и печатает сводный баланс по категориям.

3.4 **Haskell.** Два текстовых файла читаются построчно, простым алгоритмом наибольшей общей подпоследовательности определяются добавленные, удалённые и совпадающие строки; отчёт выводится в консоль и сохраняется в отдельный файл.

## Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Сервер для игры в крестики-нолики между двумя клиентами | Rust | `4_task_1_rust` |
| 2 | Сервер очереди задач с воркерами-процессами | Elixir | `4_task_2_elixir` |
| 3 | Сервер синхронизации общего счёта для нескольких клиентов | Swift | `4_task_3_swift` |
| 4 | Эхо-сервер с журналированием обращений | Scheme | `4_task_4_scheme` |

4.1 **Rust.** Сервер на сокетах и потоках сопоставляет пары подключившихся клиентов в отдельную игровую сессию, транслирует ходы между игроками и определяет победителя; несколько сессий обслуживаются параллельно.

4.2 **Elixir.** Клиенты по TCP отправляют серверу текстовые задания на вычисление; сервер-диспетчер распределяет их между несколькими процессами-воркерами (акторная модель `gen_tcp`) и возвращает результат отправителю.

4.3 **Swift.** Несколько клиентов подключаются к серверу и по очереди изменяют общий игровой счёт; сервер поддерживает согласованное состояние и после каждого изменения рассылает всем подключённым клиентам текущее значение.

4.4 **Scheme.** Сервер на сокетах отвечает на команды `ECHO text`, `TIME` и `UPPER text`; каждое обращение клиента (адрес, команда, время) записывается в файл-журнал на сервере.

## Тема 5. Конвертация данных из одного формата в другой

Папка: `5_convert/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | INI в JSON | Clojure | `5_task_1_clojure` |
| 2 | CSV в таблицу Markdown | Erlang | `5_task_2_erlang` |
| 3 | JSON в S-выражения | OCaml | `5_task_3_ocaml` |
| 4 | BMP в ASCII-art | Zig | `5_task_4_zig` |

5.1 **Clojure.** Собственный парсер INI-файлов (секции `[section]`, пары `key=value`, комментарии `;`) переводит структуру в JSON-объект вида `{"section": {"key": "value"}}` с корректным экранированием строк и отступами.

5.2 **Erlang.** CSV разбирается построчно с учётом кавычек; из первой строки формируется заголовок таблицы Markdown, из остальных — строки таблицы с выравниванием столбцов по символу `|`.

5.3 **OCaml.** Рекурсивный разборщик JSON строит дерево из объектов, массивов, строк, чисел и `true/false/null`, а затем печатает его в виде вложенных S-выражений: объекты — как списки пар `(key . value)`, массивы — как списки значений.

5.4 **Zig.** Читается простой BMP-файл (заголовок + пиксели), каждый пиксель переводится в оттенок серого и сопоставляется символу из палитры плотности; результат построчно выводится в консоль и сохраняется в текстовый файл.
